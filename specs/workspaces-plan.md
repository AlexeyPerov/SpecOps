# План развития Workspaces

Обновлено: 2026-10-18. Статус: WS-01–WS-05 завершены; WS-06–WS-08 не начаты.

Цель — удобно работать с каталогом из 30 и более проектов: находить нужный workspace, группировать и закреплять проекты, видеть Git-состояние и освобождать ресурсы закрытых контекстов. Индикаторы работы агентов в этот план не входят.

## Исходное состояние

- [ActivityRail](../app/src/lib/components/ActivityRail.svelte) показывает плоский список открытых в окне workspaces. Есть узкий и развёрнутый режимы, изменение ширины и ручной порядок через drag-and-drop. Карточки содержат имя, путь и счётчики Sessions/Tabs.
- [WorkspaceManagerView](../app/src/lib/components/WorkspaceManagerView.svelte) показывает тот же список, включая скрытые из панели проекты. Есть добавление одного или нескольких каталогов, настройки и переход в Version Control.
- [workspacePreferences](../app/src/lib/services/workspacePreferences.ts) хранит общие для окон предпочтения по пути проекта: видимость в панели и место хранения документов.
- [workspaceManagerGitColumn](../app/src/lib/git/workspaceManagerGitColumn.ts) уже предоставляет Git-сводку, кэш на 60 секунд, объединение обычных одновременных запросов по пути и обновление после Git-операций. Manager ограничивает пакетную загрузку четырьмя workspace одновременно; результаты публикуются после завершения пакета. Принудительное обновление сейчас обходит объединение запросов.
- [repositoryStatusSummary](../app/src/lib/git/repositoryStatusSummary.ts) читает ветку, ahead/behind и наличие изменений через `git status -sb`; для detached HEAD нужен дополнительный запрос. Отдельного поля конфликтов в сводке пока нет.
- [appShellEffects](../app/src/lib/services/appShellEffects.ts) подключает наблюдение дерева ко всем открытым корням при активном workspace; [реестр каталогов файлов](../app/src/lib/services/workspaceFileCatalogRegistry.ts) сохраняет посещённые каталоги до освобождения. Поэтому стоимость 30 проектов определяется также наблюдателями и кэшами, а не только отрисовкой списка.
- [Перенос между окнами](../app/src/lib/services/workspaceWindowTransfer.ts) уже сохраняет рабочий контекст. Повторное открытие занятого проекта фокусирует его окно. Эти гарантии сохраняются.

## Целевая модель

### Каталог и открытые контексты

Каталог — общий для приложения список добавленных проектов. Запись содержит стабильную идентичность нормализованного корня, имя для отображения, принадлежность к папке, ручной порядок, закрепление и предпочтения видимости. Идентификаторы `ws-*` остаются идентификаторами открытого контекста, а не постоянной идентичностью проекта.

Открытый контекст принадлежит конкретному окну и содержит редакторы, вкладки, буферы и ссылки на сессии. Закрытие контекста сохраняет проект в каталоге. Сохранённый контекст можно открыть повторно с восстановлением вкладок и layout; содержимое файлов перечитывается с диска, а несохранённые буферы проходят существующий Save/Discard/Cancel. Снимок закрытого контекста не держит редакторы и наблюдатели в памяти.

Новая модель записывается сразу в актуальном формате. Миграции старых сохранённых данных, совместимые декодеры и автоматическое преобразование прежних файлов не входят в реализацию. Это не отменяет сохранность данных, созданных уже в новой модели, и восстановление после сбоя.

### Папки и закрепление

- Папка — логическая группа проектов внутри SpecOps, без изменений на диске. Один уровень; проект относится максимум к одной папке. Остальные находятся в «Без папки».
- Папки, принадлежность, закрепление и ручной порядок общие для окон. Раскрытие папок, поиск и прокрутка принадлежат окну. Логические папки не меняют владение workspace окном.
- Можно создать, переименовать и удалить папку. Удаление переносит её проекты в «Без папки» с сохранением относительного порядка.
- Раздел «Закреплённые» расположен сверху. Закреплённый проект показывается там один раз; его принадлежность к папке сохраняется. Снятие закрепления возвращает его в порядок папки.
- Скрытие из панели имеет приоритет над закреплением. Проект остаётся доступен в Manager и быстром переключателе.
- В обычном режиме панель показывает проекты текущего окна и доступные закрытые проекты каталога. Проекты другого окна доступны через Manager и переключатель; их выбор фокусирует владельца. Панель не дублирует открытые контексты между окнами.

### Панель и навигация

- Развёрнутый режим: имя и вторая строка Git; ориентир высоты 44–48 CSS px. Полный путь — в tooltip, а для одинаковых имён — короткий различающий фрагмент рядом с именем. Sessions/Tabs убрать из постоянной строки; при необходимости оставить в tooltip.
- Узкий режим: аватар/инициалы, небольшой Git-значок и разделители групп. Свёрнутая группа остаётся доступной отдельной кнопкой с меню её проектов; полные имена доступны через tooltip и переключатель. Добавить цвет/значок проекта как необязательное локальное предпочтение для различения одинаковых инициалов.
- У панели есть фильтр по имени и пути. Совпадения внутри свёрнутых папок временно раскрываются; очистка фильтра возвращает сохранённое раскрытие. Отдельные состояния «Каталог пуст» и «Совпадений нет».
- Быстрый переключатель открывается отдельной командой с сочетанием клавиш, выбранным после проверки существующих привязок. В нём доступны все проекты, включая скрытые и открытые в другом окне; строки показывают группу и состояние открытия. При пустом запросе последние использованные идут первыми, при поиске — сначала релевантность, затем давность использования.
- Добавить команду возврата к предыдущему workspace, исключая закрытые и недоступные контексты. Историю обновляет фактическая активация проекта, а не наведение, поиск или открытие Manager в Notepad. Manager не должен подменять предыдущий workspace служебным переходом в Notepad.
- Обычный порядок панели стабилен. Автоматическая сортировка по последней активности применяется к переключателю; сортировку Manager можно менять отдельно.

### Git в панели и Manager

Один общий сервис отдаёт компактную сводку: ветка или detached HEAD, наличие изменений, наличие конфликтов, локальные ahead/behind, время последней успешной проверки и состояние загрузки/ошибки. Панель и Manager подписываются на одни данные. Подробная файловая модель Version Control сохраняется; её результаты и события по возможности обновляют сводку без повторной команды.

- В развёрнутой панели показывать ветку, ненулевые `↑/↓` и компактный маркер изменений; конфликты выделять сильнее. В узкой — значок, расшифрованный в tooltip и доступном имени.
- Различать неизвестно, проверяется впервые, актуально, устарело, не Git и ошибка. При фоновом обновлении сохранять предыдущие данные; ошибка не превращает их в «чисто».
- Ahead/behind относится к локально известной upstream-ссылке. Панель не запускает `fetch`; tooltip объясняет смысл счётчиков.
- Ключ сводки соответствует конкретному рабочему дереву: несколько подпапок одного дерева используют результат совместно, разные linked worktrees сохраняют отдельные статусы. Общие изменения refs инвалидируют затронутые деревья.
- Стартовая политика: актуальность 60 секунд; объединение файловых событий за 300–500 мс. Истечение срока делает запись устаревшей, но само по себе не запускает обход всего каталога.
- Очередь фоновых сводок общая в пределах приложения, включая окна. Начальный предел — четыре одновременные проверки, с приоритетом активного проекта, затем видимых строк. Ограничение включает разрешение корня репозитория, чтобы оно не создало отдельный неконтролируемый поток процессов. Сохранить существующие очереди и ограничения Git runner.
- Холодная загрузка проверяет только активный проект и видимые строки. Свёрнутые группы, скрытые и закрытые проекты без видимого потребителя не проверяются. Видимые закрытые проекты можно проверить без открытия рабочего контекста.
- Событие файловой системы или Git-операция инвалидирует нужный корень; активный/видимый потребитель получает отложенное обновление. Учесть внешнее переключение ветки и изменения Git metadata, в том числе linked worktrees, без рекурсивного наблюдения всего каталога.
- Принудительный refresh обходит TTL, но сохраняет объединение выполняющихся запросов и лимиты. Если изменение произошло во время чтения, запланировать одну следующую проверку; поздний ответ не может затереть более свежую сводку.
- Результаты публикуются по мере готовности отдельных проектов. Один медленный репозиторий не задерживает все строки. Отмена ожидания не означает остановку subprocess: учитывать его до завершения или подтверждённой нативной отмены.
- При скрытом/неактивном окне не начинать фоновый обход; возврат фокуса перепроверяет только нужные устаревшие строки. Невостребованные кэши ограничены по размеру и освобождаются.
- Учитывать текущие настройки включения Git и фоновых проверок. При запрете фонового Git панель не создаёт subprocesses.

## Этапы реализации

Каждый этап включает запись в changelog, целевые проверки и сохранение существующего поведения открытия, закрытия и переноса workspace. До начала задач снять baseline на текущей версии. Порядок зависимостей: WS-01 → WS-02 → WS-03 → WS-04 → WS-05 → WS-06 → WS-07 → WS-08.

### WS-01 Каталог и хранение предпочтений

Статус: выполнено 2026-10-18. Каталог и предпочтения объединены в атомарном native-хранилище с OS-lock, восстановлением проверенной резервной копии и межоконными уведомлениями. Manager показывает зарегистрированные закрытые/недоступные проекты; модель и API сохранённого контекста готовы для WS-07. Проверки: 309 frontend-файлов / 3139 тестов, 8 native-тестов каталога, Svelte/type check без ошибок и предупреждений, production build.

- Ввести доменную модель проекта и папки, отдельную от `WorkspaceEntry`. Стабильная идентичность использует текущую политику нормализации путей, включая проверку дублей.
- Хранить каталог и настройки атомарно, сериализовать изменения между окнами, уведомлять подписчиков после записи. Не создавать несколько конкурирующих источников истины для скрытия и закрепления.
- Связать добавление одного и нескольких workspace с регистрацией в каталоге. Ошибка открытия не должна оставлять фиктивный открытый контекст; уже зарегистрированный недоступный проект остаётся в каталоге с объяснимой ошибкой.
- Подключить каталог к текущему Manager, пока сохраняя рабочий путь к существующим открытым контекстам. Включить модель сохранённого закрытого контекста; полный интерфейс управления появится в WS-07.

Готово, когда добавленные проекты сохраняются после перезапуска, два окна не теряют одновременные изменения, повторный путь не создаёт дубль, а открытие занятого проекта фокусирует владельца. Проверить ошибки записи и восстановление последнего целого файла.

### WS-02 Компактные строки и различимость проектов

Статус: завершён 2026-10-18. Строки 46 px, различающие фрагменты путей, цвет/символ в общем каталоге, клавиатурные активация/контекстное меню/порядок/ширина. Git пока отображает «не проверен» без запросов. Проверены 34 целевых теста, Svelte/types без диагностик и production build. Проверка реального desktop, масштабов и снимки включены в WS-08.

- Заменить развёрнутые карточки компактными строками, добавить место под Git-сводку без обязательного запроса данных на этом этапе.
- Сохранить изменение ширины, узкий режим, контекстные действия, drop файлов и ручное переупорядочивание.
- Добавить различение одинаковых имён коротким путём, настройку цвета/значка и явный focus. Иконка или цвет не заменяют текстовое доступное имя.

Готово, когда 30 записей удобно прокручиваются, длинные имена не ломают layout, одинаковые имена различимы, а мышь и клавиатура позволяют активировать каждый проект. Проверить несколько ширин панели и масштабов интерфейса.

### WS-03 Папки и закреплённые проекты

Статус: завершён 2026-10-18. Панель строится из каталога с закреплёнными сверху, без дублей, скрытых и проектов другого живого окна; закрытые записи открываются по пути без фиктивного контекста. Папки поддерживают CRUD, порядок, сворачивание, счётчики и меню в узкой панели. Native-транзакции сохраняют скрытые позиции и изменения других окон; назначение папки не снимает закрепление, удаление папки дописывает проекты в «Без папки» в прежнем относительном порядке. Раскрытие и прокрутка хранятся по окну; фильтр временно раскрывает секции и отключает порядок DnD. Проверки: 52 целевых frontend-теста, 11 native-тестов каталога, Svelte/type check без диагностик, production build. Реальный desktop/restart и снимки — WS-08.

- Добавить создание, переименование, удаление, сворачивание и порядок папок; действия назначения папки и закрепления через контекстное меню.
- Расширить drag-and-drop: порядок внутри папки, перенос между папками, перенос в закреплённые и порядок самих папок. Меню даёт клавиатурную альтернативу каждому действию.
- На время фильтрации или автоматической сортировки отключать неоднозначное перетаскивание порядка; назначение папки через меню остаётся доступным.
- Восстанавливать раскрытие папок и прокрутку окна; показывать счётчик проектов, фактически находящихся в секции с учётом видимости и закрепления.

Готово, когда операции не меняют пути и владение окнами, удаление папки сохраняет проекты, закреплённые не дублируются, а переупорядочивание работает и при скрытых записях. Проверить reload и синхронизацию между окнами.

### WS-04 Поиск и быстрый переход

Статус: завершён 2026-10-18. Общий локальный fuzzy-поиск по имени/пути подключён к панели, Manager и лениво загружаемому переключателю; ввод читает каталог без Git и обхода файлов. Панель временно раскрывает совпадения и восстанавливает сохранённое сворачивание после Escape; доступны стрелки и Enter, поиск есть в обеих ширинах. Переключатель включает скрытые проекты и владельцев других окон, показывает папку/состояние, сортирует по релевантности и затем последнему использованию, возвращает фокус после закрытия. История окна учитывает завершённые активации, исключает provisional add/transfer rollback и служебный Notepad-переход Manager; предыдущий проект выбирается из открытых доступных контекстов. Команды зарегистрированы в меню/палитре: Cmd/Ctrl+Alt+P и Cmd/Ctrl+Alt+Left; конфликты привязок проверены на обеих платформах. Полный frontend suite: 316 файлов / 3176 тестов; Svelte/type check без диагностик, production build, Svelte autofixer без issues. Реальные desktop/multiwindow сценарии и визуальная приёмка остаются в WS-08.

- Добавить общий локальный поиск по имени/пути для панели, Manager и отдельного переключателя. Поиск читает каталог без обхода диска и без запуска Git.
- Реализовать временное раскрытие совпадений, очистку через Escape, навигацию стрелками, Enter и возврат фокуса после закрытия переключателя.
- Добавить историю успешных активаций и команду предыдущего workspace. Переход в другой контекст сохраняет текущие гарантии буферов и фоновых сессий.
- Проверить конфликты клавиш; зарегистрировать команды в существующей системе команд и меню.

Готово, когда проект находится по части имени/пути независимо от раскрытия и скрытия, другой владелец корректно фокусируется, очистка восстанавливает список, а открытие переключателя не меняет активный workspace. Недоступный проект выдаёт ошибку и не становится успешной записью истории.

### WS-05 Общий сервис Git-сводок

Статус: выполнено 2026-10-18. Подписки Manager используют общий native-планировщик с четырьмя lease, приоритетами и учётом subprocess до завершения текущего Git runner. Добавлены canonical worktree dedup, TTL/stale/error, конфликты, force coalescing, revision/publication guards, отложенная инвалидизация и узкие demand-наблюдатели `.git`/common refs. Фокус, видимость и настройки снимают фоновый спрос; неиспользуемые кэши ограничены. Проверки: 317 frontend-файлов / 3186 тестов, 14 native-тестов сервиса/наблюдателей/lifetime, 48 native-тестов Git runner, Svelte/type check 0/0 и production build. Реальные desktop-сценарии и метрики двух окон входят в WS-08.

- Выделить существующий Git-кэш Manager в сервис с подписками, временем актуальности, инвалидированием и объединением запросов, включая force-refresh.
- Добавить наличие конфликтов в компактный результат. Переиспользовать текущие Git API/runner, а не создавать второй backend; подробный diff и список файлов не загружать ради панели.
- Реализовать общий для окон бюджет фоновых проверок, приоритеты, защиту от устаревших ответов и ограничение памяти. Если общий планировщик требует нативной координации, включить её в этот этап.
- Подключить события Git и подходящие существующие файловые наблюдатели. Для внешних Git metadata изменений добавить узкое наблюдение только востребованных деревьев с учётом `.git`-файла.
- Перевести Manager на подписку с публикацией результатов по одному; убрать независимые пакетные запросы из компонента.

Готово, когда одновременные потребители одного дерева не дублируют проверку, два окна соблюдают общий предел, invalidation во время чтения не теряется и медленный/ошибочный репозиторий не блокирует остальные. Проверить detached/unborn HEAD, конфликты, отсутствие upstream/Git, подпапки, linked worktrees, timeout, force-refresh и отключённый фоновый Git.

### WS-06 Git в панели

- Подписывать строки на сервис в зависимости от видимости и раскрытия. Изменение ширины, фильтра и прокрутки меняет приоритеты без повторных одинаковых запросов.
- Добавить компактную сводку и tooltip, состояния устаревания/ошибки и переход в Version Control через отдельное действие, не перехватывающее обычное переключение проекта.
- Добавить refresh одной строки и обновление видимых строк. В Manager отдельная явная команда обновляет отфильтрованный список в той же очереди.

Готово, когда холодное открытие панели не проверяет все 30 проектов, неизменившиеся видимые данные в пределах TTL не вызывают новые процессы, а невидимый репозиторий после изменений корректно перепроверяется при появлении. Значки сохраняют смысл в обеих ширинах и не различаются только цветом.

### WS-07 Управление каталогом и освобождение контекстов

- Сделать Manager обзором всего каталога с областью «Все проекты» по умолчанию и фильтрами «В этом окне», «В другом окне», «Закрытые», «Скрытые». Добавить поиск, сортировку по имени/последнему использованию/ручному порядку и отображение папки, закрепления, Git и состояния открытия.
- Добавить множественное выделение и пакетные действия: назначить папку, закрепить/открепить, показать/скрыть в панели. Выбор checkbox и modifier-click не активируют workspace. Ошибки отдельных записей показываются без ложного общего успеха.
- Разделить команды «Закрыть workspace» и «Убрать из каталога». Закрытие сохраняет запись, настройки и последний контекст; удаление записи доступно для закрытого проекта и не удаляет файлы, документы и историю сессий.
- Закрывать через существующие проверки сохранения и ограничений активных операций. Не завершать автоматически работающие сессии ради очистки памяти; если контекст пока нельзя освободить, объяснять причину и не помечать его закрытым.
- Освобождать наблюдатели, редакторы, каталоги файлов, таймеры и невостребованные данные Git закрытого проекта. При повторном открытии восстанавливать layout и валидировать доступность файлов; пропавший путь сохранять как недоступную запись.
- Обновить описания текущего поведения в документации по workspace и окнам после реализации новой семантики.

Готово, когда закрытый проект открывается из панели/Manager/переключателя без повторного выбора папки, вкладки восстанавливаются, скрытие не закрывает контекст, а закрытие не удаляет проект из каталога. Проверить отмену сохранения, ошибку flush, перенос между окнами, закрытие окна и восстановление приложения. Ресурсы возвращаются к уровню реально открытых контекстов без роста после повторных циклов.

### WS-08 Приёмка на 30 проектах

- Подготовить воспроизводимый набор: 30 проектов в пяти папках, закреплённые и скрытые записи, одинаковые имена, длинные пути, недоступный каталог, обычные Git-репозитории, большой репозиторий с untracked-файлами и linked worktrees.
- Снять метрики до/после: холодный запуск, первое отображение панели, открытие Manager, поиск, переключение, количество и максимальный параллелизм Git-процессов, активные наблюдатели и память. Отдельно сравнить 30 закрытых проектов в каталоге, 5 открытых и 30 открытых контекстов.
- Проверить серию открытий/закрытий и переходов между проектами, два окна, шквал файловых событий, внешнее переключение ветки, уход/возврат фокуса и restart.
- Выполнить целевые тесты доменной модели, хранения, очереди и компонентов; проверки типов/Svelte, production build и затронутые native tests. Реальные desktop-сценарии и снимки панели в двух ширинах сохранить вместе с результатами замеров.

Измеримые условия приёмки:

| Проверка | Условие |
| --- | --- |
| Общая очередь сводок | Не более четырёх выполняющихся фоновых проверок во всех окнах вместе |
| Каталог без потребителей | Нет Git-процессов и рекурсивных наблюдателей только из-за наличия закрытой записи |
| Повторный показ в пределах TTL | Нет повторных Git-процессов без invalidation или явного refresh |
| Поиск по 30 проектам | Предварительная цель p95 до 50 мс от ввода до результата на одной фиксированной машине |
| Смена проекта | Панель и кэшированная сводка показываются без ожидания Git; p95 восстановления не хуже baseline более чем на 10% при одинаковом наборе вкладок |
| Неактивное окно | Нет периодического полного опроса каталога |
| Освобождение | После повторных циклов открытия/закрытия нет накопления наблюдателей, подписок и неограниченного роста кэшей |
| Отказ одного проекта | Другие строки обновляются, ввод и навигация остаются доступны |

Порог поиска и допустимая разница времени переключения — цели для приёмки, а не уже подтверждённые характеристики. В отчёте указывать машину, сборку, число повторов и исходные/итоговые значения; отдельно объяснять неизбежный объём открытых буферов.

## Границы работ

В план не входят индикаторы работы агентов, вложенные папки нескольких уровней, автоматическая группировка, удаление проектов с диска и фоновый сетевой опрос Git. Не добавлять автоматическую приостановку или завершение агентских сессий. Для 30 строк начинать с обычного списка; виртуализацию вводить только при подтверждённой проблеме измерений, сохраняя фокус, drag-and-drop и наблюдение видимости.

## Основные точки изменения

- UI: `ActivityRail`, `workspaceRailDragController`, `WorkspaceManagerView`, `WorkspaceSettingsView`, существующие picker-компоненты и маршрутизация `+page.svelte`/`AppShell`.

Названия новых модулей определить при реализации. Каждый этап закрывать по его критериям; наличие UI без работающего хранения, обновления или освобождения ресурсов не считается завершением.
