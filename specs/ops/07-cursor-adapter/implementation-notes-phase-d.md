## User setup and support

Create/select a local Cursor profile in Sessions. Put a private API/service key in that profile's `api-key` import file, then connect it. The host consumes only a successfully verified import; failed/offline imports remain for explicit retry. Browser/device lifecycle and Cloud routing/storage/navigation remain unavailable. Pick a model from that profile's current native catalog; no model entitlement is inferred from listing alone.

New sessions default to `none` tools and enabled native sandbox. File-read/file-write presets and model enum settings are immutable after binding. File edits/deletes run automatically under native policy when explicitly selected. Native workspace/private-profile sandbox configuration can apply independently; there is no OS read-only or confinement guarantee. Approvals/questions/hooks/MCP/skills/task/fork/restore are unavailable as documented in the [finite capability ledger](implementation-notes-phase-c.md).

Stop requests native cancellation and closes only owned workers; it does not undo file changes. Restart retires the selected profile's generation and explicitly hydrates the same native agent from its private JSONL store. Logout removes only that profile's credential and retires its owned work; bindings/native history/workspace files remain. An original credential digest is required for existing sessions; reconnecting another key never transfers them. Missing native history or lost acknowledgements retain bindings and require inspection; a fresh session must be an explicit user choice. No automatic resend or compatibility migration exists. Support snapshots contain bounded versions/protocol/profile ID/auth category/generation/health/recovery only, excluding labels, keys, homes, raw native events/tool output and account URLs.
