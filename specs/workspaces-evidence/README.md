## Reproduction

No remotes/network operations are needed.
2. Build from `app`: `npm run tauri build -- --debug --bundles app --config '{"productName":"SpecOps Workspaces Acceptance","identifier":"com.alexeyperov.specops.workspacesacceptance"}'`. Stop that app before seeding. `python3 scripts/seed-profile.py --manifest /path/manifest.json --open 0 --force` writes only the explicitly isolated acceptance profile; repeat with `--open 5` or `--open 30`. `--width 64` sets the matched rail. Preserve evidence before resetting the disposable profile. The script uses the current catalog/session codecs, without migrations.
3. Use the real native application and Web Inspector. Paste `native-evidence.js`, schedule `window.__evidence.later(()=>window.__evidence.capture('label'))`, then close Inspector. JSON is written under the acceptance profile. The helper resolves the running application's app-data directory. `exact-root-cycles.js` verifies UI close state, persisted saved context and actual root membership over ten cycles; a zero watcher count while Manager is selected alone does not prove a context closed.
4. For matched pointer timing, paste `pointer-timing.js`, close Inspector, make 45 actual pointer actions in the repeating order project-02/project-03/project-04/shared-project, three runs. Current native pixel coordinates are x36 and y690/758/827/296; baseline x64 and y242/314/386/170. Recheck geometry before reusing coordinates. Clear `samples.length=0` between runs, not during a run. The event records its own viewport; the top-level export viewport is 800×520 while Inspector is open and is **not** the measured viewport. Export each run, including failures.
5. Original baseline source/bundle were preserved outside git before implementation. For exact native before-counts, `instrument-baseline.py` applies only the accompanying read-only counter/watcher diagnostic patch to that archive. It does not add catalog behavior. Original pointer timings use the uninstrumented original bundle. `seed-baseline.py` and `seed-instrumented-baseline.py` target separate isolated profiles. Pass `--manifest /path/manifest.json --open 5|30` to baseline seed helpers and `--source /archived/checkout --patch /new/output.patch` to the instrumentation helper. Reproduction does not depend on the capture's `/tmp` directory.
6. `python3 scripts/analyze.py` recomputes the pointer summary from committed raw evidence. Percentiles use nearest rank, `ceil(.95*n)-1`; no timeout is removed because activation was slow. Successful same-context clicks are excluded from transition timings.

The strict matched pointer comparison measures pointer release through two animation frames and verified target activation. It confirms the 10% target **for that empty-context UI path**. It is not heavy document, agent-session or file-buffer restoration latency. Baseline native `workspace.switchRestore` initially produced only five first-visit samples (1,1,2,2,2 ms); warm revisits do not emit that metric consistently, so those numbers cannot establish a service-restore p95. Per-run final pointer p95 is 41/33/32 ms, baseline 35/31/31 ms. In baseline run 1 one pointer-up had no preceding captured pointer-down/previous context and timed out; it remains in the all-run attempt statistics as a failure. Runs 2+3 avoid this focus ambiguity and contain the same 88 actual transitions on each build. No slow selected:false sample was silently discarded.

Earlier synthetic `.click()` baseline samples never activated the old draggable rows and are explicitly invalid. The preliminary `baseline-matched-pointer.json` has 44 valid transitions/p95 39 ms. The pre-optimization final idle run is p95 46 ms; another final run overlapped native tests (p95 55 ms) and is preserved as contaminated. Neither replaces the declared three-run comparison. WebKit measured 108 repeated timestamp formats at mean 3.63 ms / max 6 ms across 30 batches; shared formatting took mean 0.10 ms / max 1 ms. Memoizing immutable presentations and sharing the timestamp formatter removed that measured repeated work before the final series.

The startup observations show a cost increase; no startup improvement or startup regression threshold is claimed. Main-process RSS also increased in the single sample. Snapshot, summary and catalog state add memory even with empty buffers; this capture does not attribute the increase precisely or prove total heap stability. Real open buffers will add their own content memory. Repeated-cycle resource membership and bounded cache counts below are stronger evidence about cleanup than this single RSS observation.

## Native resource matrix

`gitProcessesStarted` counts successful native Git child creations, including executable version probes and explicit Git operations; failed process creation does not increment it. `commandsStarted/Finished` count accepted summary-runner lifetimes, which can fail before spawning a child. `maxActiveCommands` and `maxActiveLeases` are exact guard/lifetime counters, not samples. Each summary runner awaits its children before releasing its guard, so peak guarded commands ≤4 is a strict bound on its actual simultaneous children. This is not a measured peak for unrelated foreground Git operations.

## Functional / visual acceptance

- Real restart without reseeding retains 30 contexts, catalog groups/pins/hidden metadata and saved snapshots. Ordinary README was closed, changed externally, reopened, and displayed the new heading. Dirty Cancel retained the context; Discard removed it while the on-disk file remained unchanged. Targeted tests cover Save all races and recovered dirty/large/missing/BOM files.
- Two real native windows exercise the switcher, ownership focus and secondary close/reuse. The first acceptance run exposed a stale open-file owner after window destruction; the fixed happy path is recorded. Deferred-release, failed-release/unreadable-registry and canceled-close regressions prove that destruction waits, errors keep the window/restart entry usable, and canceled persistence does not release ownership. Existing startup pruning remains the recovery path for already-crashed owners; no persisted-data migration was added.
- Actual native geometry checks bound rail/list and Manager bottom to the viewport. Expanded240 and narrow64 screenshots, minimum48 at125%, and Manager240 at125% are saved. Max520 also stays bounded. Manager horizontal scroll reaches the right-hand actions: clientWidth514, scrollWidth1441, scrollLeft927, action right762.625 inside Manager right783. Duplicate names retain distinguishing paths, long names truncate, hidden projects remain searchable, and missing-root failures do not block other rows/search. Component tests cover keyboard activation/reorder/width, Escape/focus, groups, pinning, batch controls and display states.
- Native diagnostics are shared across windows, preserve running lifetime ownership during demand changes, and expose exact cumulative spawn counts. A parallel-safe spawn test uses its own local atomic counter. Unit/native tests cover TTL, forced refresh coalescing, inactive invalidation→focus, cancellation, linked metadata, conflicts and stale/error presentation.

## Acceptance fixes and validation

WS-08 fixed four issues found in real desktop scenarios: rail flex overflow requested offscreen Git work; detached chat copies caused every populated-chat close to abort; blur removed metadata invalidation watches; and asynchronous file-claim cleanup after destroyed windows prevented file reuse. QA additionally fixed dirty recovery being erased by a large-file gate, stale missing/BOM metadata on disk reread, concurrent same-root restored opens/ownership rollback, Save all re-edits/new dirty documents during awaited close work, and transferred preview-cache retention. All have targeted regressions. Timestamp presentation optimization follows the measured WebKit hot path.

Final validation: **322 frontend files / 3230 tests passed** (`--maxWorkers=4`), **Svelte/types 0 errors/0 warnings**, production frontend/native debug application build passed, **159 native library tests passed serially, one existing ignored** managed installer probe. Svelte autofixer for the rail reported issues=[]; generic subscription/Map suggestions were reviewed without unrelated refactoring. One unconstrained concurrent run hit existing markdown-fold timing and a 5000-row history timeout; its raw failure log is retained, followed by the complete bounded passing run. Native tests run serially because an existing Agent Host lease test can report Busy under parallel execution.

An existing favorites notification appears in isolated profiles: native `fs.exists` rejects the app-data favorites path under its capability scope, including when an empty current-format file exists. `raw/favorite-error.json` records the exact error. This unrelated capability issue is not presented as a clean favorite-feature acceptance and was not changed. It does not invalidate catalog/ownership/watcher evidence. The original baseline showed the same notification. No network fetch, OS-cold-launch, renderer-wide memory, heavy-buffer p95 or arbitrary long-duration leak claim is made.
