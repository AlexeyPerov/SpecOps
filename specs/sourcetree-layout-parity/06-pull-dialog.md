# GL-06 — Окно Pull

**Статус:** Planned. **Зависимости:** GL-05; расширение remote API и состояния Git-операций для дополнительных опций.

![Референс окна Pull](references/pull-dialog.png)

## Layout и взаимодействия

- [ ] Открывать modal с repository selector, строкой URL, remote branch selector и Refresh, неизменяемым именем локальной целевой ветки, блоком Options и нижними Cancel / Pull.
- [ ] Repository selector содержит настроенные remotes. Custom из референса требует отдельной поддержки URL и проверки ввода; до этого вариант недоступен с объяснением. URL отображать без раскрытия встроенных credentials.
- [ ] Загружать список веток выбранного remote; Refresh обновляет список, выбор remote отменяет/игнорирует старый ответ. Явные loading/empty/auth/error states.
- [ ] Показать опции: немедленный commit merge; включение сообщений объединяемых коммитов; отдельный merge commit при fast-forward; rebase вместо merge.
- [ ] При выборе rebase отключать merge-only опции и не отправлять сохранённые скрытые значения. Текст кратко объясняет изменение локальной истории.
- [ ] Не копировать unchecked defaults со снимка. Явно определить initial values из поддержанной стратегии/настроек репозитория; пользователь видит фактическую стратегию до запуска.
- [ ] Primary action доступен только при валидной паре remote/branch, допустимом текущем состоянии и поддержанных опциях. До выполнения повторно проверить repo/HEAD/целевую ветку.
- [ ] Escape/Cancel до запуска закрывает окно без Git-мутации. Во время операции есть progress и Cancel operation; закрытие UI не означает успешной отмены процесса.

## Git-зависимости, обязательные для рабочих опций

- [ ] Добавить query remote heads (существующего remote tags API недостаточно), типизированные pull options и проверенные формы native argv.
- [ ] Определить mapping commit/no-commit, log/no-log, no-ff и rebase; не полагаться на случайные глобальные настройки. Проверить взаимные ограничения.
- [ ] Режим без commit может оставить merge незавершённым; fast-forward не создаёт merge commit даже при no-commit. Реальный результат показать в Changes и состоянии репозитория.
- [ ] Rebase/merge conflicts, continue/abort и восстановление после перезапуска требуют отдельного механизма операций. Пока его нет, соответствующие новые опции заблокированы и полная задача остаётся открытой.
- [ ] Операцию проводить через существующую авторизацию, pre-git guard, mutation queue, отмену и refresh pipeline. Ошибка и отмена после начала требуют перечитать Git-состояние.

## Приёмка

- [ ] Состав и порядок полей соответствуют референсу, длинные URL/refs не ломают окно; клавиатурный фокус остаётся в modal и возвращается к Pull после закрытия.
- [ ] Cancel до запуска не меняет repo. Смена HEAD при открытом окне блокирует применение старого запроса либо требует его повторного просмотра.
- [ ] На локальном тестовом remote проверены обычный pull, diverged branches, rebase, no-commit/no-ff, auth/error/cancel; не реализованные варианты явно отмечены blocked.
- [ ] Результат подтверждён Git, отсутствуют неработающие переключатели, выдающие успешный результат.
