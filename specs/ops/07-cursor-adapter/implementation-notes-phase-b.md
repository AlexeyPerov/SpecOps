# AS07-B — Durable local agents, runs and recovery

Recorded: 2026-10-05 00:01 MSK. Source lifecycle verified; authenticated inference, native policy and signed installed acceptance remain open.

## Selected native contract

The exact official local SDK 1.0.35 and bundled Node 24 from [A's feasibility ledger](implementation-notes-phase-a.md) remain the supported source contract. B uses public `Agent.create`, `Agent.resume`, `SDKAgent.send`, `Run.stream`, `Run.wait`, `Run.cancel` and async disposal. No model-client wrapper, Cloud execution, global CLI, account rotation or prompt policy is introduced.

Each native agent owns a separate explicit `JsonlLocalAgentStore` under its private profile. This avoids concurrent SDK JSONL rewrite operations across unrelated sessions. Native `agentId` is the durable session identity; `runId` remains turn-scoped. A private atomic/fsynced binding records canonical workspace, selected native catalog model, agent mode, minimal settings, original credential digest, monotonic host cursor and client-message/run mapping. The native agent's SDK metadata separately records the same immutable binding; resume checks both before use. Missing native storage preserves application metadata and returns a typed missing-session error.

An actual account-free SDK probe establishes a subtle lifecycle detail: creation reserves one initial native queued run with null request/start/checkpoint while the agent remains idle. The first send may use only that untouched initial run. Blank reserved runs do not fabricate assistant history. Later queued/running work is not treated as idle, and ambiguous host dispatches block further sends.

Pinned SDK source projects assistant/thinking updates as deltas. B maps text, reasoning, native tool status/input/results, token usage, running status and bounded unknown diagnostics. Native terminal status messages alone do not finish a turn: the stream is drained and `Run.wait` determines the sole terminal result. Tool/result events retain native identity; native routes are checked before full-envelope redaction. B exposes no direct diff or structured subagent capability because this selected stream does not provide a corresponding stable native contract. Local billed usage IDs differ from client run IDs; cost is not fabricated from token counts or agent totals.

## Lifecycle and ownership

An isolated worker process owns each operation's SDK environment/global state. Credentials cross private stdin to explicit SDK options and never become process arguments, inherited provider environment or frontend native state. SDK stdout/stderr cannot enter host framing. Workers await native cancellation/disposal; late creation after Stop is disposed. The host awaits independently owned worker/process cleanup without depending on a paused stream consumer. The existing birth-stamped descendant owner remains inside the host supervisor group.

Reservations precede asynchronous authentication/create/history/send and prevent overlapping work on one agent. Authentication mutations reserve the profile before retiring its operations; logout can invalidate an unfinished key import. Unknown auth actions fail before side effects. Restart/logout affect only their owner. Stored credentials can reconnect a fresh host through the native account/catalog control probe; a concurrently connecting profile reports an explicit retry state. Generations invalidate late native work, and the production client additionally scopes host replacement by its host epoch.

Before send, the host durably records a single-use client-message dispatch intent. It records the native run acknowledgement before mapping events. Duplicate client prompts and unresolved prior intents cannot be sent again. Known terminal native runs can be reconciled on explicit resume. A lost run acknowledgement cannot be safely correlated through the SDK's text-only local user message interface; it remains an explicit uncertain dispatch requiring inspection/new session, never an inferred retry or automatic adoption. A lost create acknowledgement leaves its private native store for inspection and does not cause a hidden second creation. Cancellation before any worker dispatch removes the unsent intent; accepted or uncertain interrupted work requires authoritative history reconciliation.

History uses native store run/event APIs and the official stream decoder. It retains native run IDs, native event identity and timestamps, normalizes every event through the same mapper, and increments the host cursor independently of native per-run sequence. Common text/tool/reasoning/usage hydration is authoritative, including interrupted runs; application caches cannot replace native history. No old prompt is replayed during resume.

## Bounds and secret boundaries

Input and individual frames are bounded to 1 MiB; prompt to 256 KiB; total worker response to 16 MiB; queued output to 4 MiB/4096 frames; text/reasoning state to 8 MiB; native history to 4096 runs/events per run with a total response bound. Native JSONL preflight allows only its four known private regular files, at most 16 MiB each/64 MiB total, rejecting symlinks and extra files before SDK reading. Worker operations have a finite timeout and cancellation grace before owned process retirement. Private host bindings use bounded no-follow regular-file reads, fatal UTF-8 decoding, exhaustive immutable-schema checks, atomic rename and file/parent fsync.

Exact credential values and generic secret shapes are scrubbed before truncation across text, tool values, object keys, IDs and complete history/event envelopes. Split native text retains unsafe suffixes until redaction can resolve them; excessive unbroken tokens fail explicitly. Credential-bearing agent/run IDs are rejected instead of attached. Errors are static/actionable, distinguishing rejected auth, quota and generic native failure without provider bodies. Native private store/checkpoint content remains native-owned; only sanitized projections cross to UI/cache/export.

## Advertised B scope and limitations

The pinned public declaration explicitly defines `tools: []` as no built-in tools/text-only and states that this restriction must be passed again on resume; each worker does so. Source native turns are enabled only for an explicit catalog model, native agent mode, `tools: []`, empty MCP configuration, `settingSources: []`, and native agent retries disabled. B accepts no additional policy/model parameter editor or attachments. It does not advertise a tested read-only filesystem guarantee: actual native enforcement remains C/live acceptance. There is no programmatic approval/question bridge, browser/device lifecycle or Cloud fallback. Stream fixtures exercise tool projections for C's later selected tool scope; they do not claim that B enables native tools.

The SDK may own internal network transport behavior; disabling native agent retries is not a promise of zero native network retries. SpecOps itself never retries a prompt after uncertain dispatch. Same-profile storage/history recovery is supported; reconnect does not reattach or automatically resume a live model run after host loss. Windows durable binding/parent-fsync and other platforms remain unaccepted rather than receiving a compatibility writer.
