# AS02-F — Native ecosystem and finite profile configuration

**Updated:** 2026-10-05 16:41 MSK
**Status:** Source implemented; authenticated/installed acceptance open.
**Prerequisite:** AS02-E; pinned app-server 0.160.0 and selected explicit experimental profile opt-in.

## Outcome

Expose native skills, current-thread tool server inventory and bounded profile-owned configuration controls in the common native session panel. Native execution owns discovery, storage, version checking and tool connection reload. Keep immutable session bindings and preserve source conversation history.

## Sequential execution

1. Generate exact native skills/configuration/MCP contracts under temporary private HOME/CODEX_HOME; verify installed pin without account/inference calls.
2. Project safe bounded native skill/server/tool/resource inventory. Host catalog tokens bind selected profile, thread, transport instance, auth revision, native generation and expiration. Managed/system skills and servers remain read only.
3. Add finite skill toggles, versioned profile web-search/reasoning-summary/verbosity writes, and connect/disconnect for already configured profile servers. Merge disabled configuration entries when native runtime inventory omits them. Consume mutation tokens before dispatch; do not replay uncertain writes.
4. Force native MCP credential file storage under the selected private home, guard known private credential/config files, mask known credentials before output truncation. Keep OAuth/elicitation and upstream development-only plugin APIs unavailable.
5. Wire the common dispatcher/client/service/panel, verify profile isolation, stale/forged targets, bounds, native CAS/lost acknowledgments, storage guards, configuration persistence, transport replacement and UI recovery. Update the finite ledger and changelog.

## Acceptance boundary

Source native contract/config probes and production fixtures are evidence for this plan. Real MCP services, OAuth, actual account/provider behavior, enforcement, signed installed/distribution and descendant cleanup remain separate open gates. No native plugin call or arbitrary configuration editor is introduced. AS02-G owns detailed subagent/context presentation and final expanded source release submission. The historical release record is unchanged.
