# AS06-C — Simultaneous named native profiles

Recorded: 2026-10-04 23:17 MSK. Source implementation verified; actual account and installed acceptance remains open.

## Profile lifecycle and immutable accounts

The common connection panel displays the stable profile UUID and native account summary. Native ChatGPT email/plan are projected only from `account/read`; API-key accounts show their actual native category without an invented email or subscription. Named create/select already existed; Codex now adds rename/remove actions. Bound session selectors remain disabled. Renaming preserves UUID, credentials and native session routing. Removing a profile retires its process, drops only its profile metadata and private credentials, publishes an explicit missing-profile snapshot and retains native history/config, durable bindings, application session metadata and workspace files. It does not select another profile for a bound thread. Unbound selection clears after removal. Other runtimes do not advertise these new CRUD actions.

A private durable per-native-ID guard records a SHA-256 principal before returning a created session. API-key principals use the exact profile-owned native key; ChatGPT principals use the native persisted account ID, not rotating access/refresh tokens or an email/plan guess. Missing/empty/unsupported identity fails closed. Pinned source verification: [native file schema](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/login/src/auth/storage.rs) and [token/account structure](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/login/src/token_data.rs). The guard is private, never returned to the WebView or support export, and survives logout and host restart. A different principal cannot read/resume the saved native thread; restoring the original principal can. API-key rotation intentionally counts as a different binding; no account-equivalence inference or migration is provided. Old records missing this new guard fail explicitly, preserving their metadata.

Private reads use bounded regular-file descriptors with no-follow, fatal UTF-8 decode and finite limits: profile/binding metadata 4 KiB, auth 1 MiB, API import 16 KiB. Binding creation is exclusive/private and fsyncs its file; metadata rename/experimental changes use atomic private replacements. A failed guard write leaves native creation uncertain; no retry or prompt replay is invented.

## Independent processes and mutation routing

Each native instance has its own `CODEX_HOME`, HOME, USERPROFILE, XDG config/data/cache and Windows app-data roots. Only ordinary execution PATH/SystemRoot/WINDIR/COMSPEC/PATHEXT/temp/locale/terminal variables survive the finite inherited environment allowlist. Ambient provider keys, runtime settings, proxy credentials, SSH agents, Node injection and global configuration paths are excluded. Tools requiring additional credentials/config must get them from deliberate native profile/workspace configuration, rather than another desktop account's environment.

Native config, MCP and skills remain native-owned in each private home plus intentional shared-workspace instructions/config. Profile management does not copy these files between homes. The same canonical workspace can be used by both processes; shared files and workspace-native settings are intentionally shared. The existing advisory writer warning/activity view identifies both session/profile IDs, uses native read-only enforcement conservatively and adds no workspace lock or account/quota rotation.

Routing remains runtime + profile + native session ID, with independent native generation and host epochs. Replacement transports inherit the previous counter before incrementing, so protocol opt-in replacement cannot reuse an old generation. Native owner/attempt/generation/principal checks run after async catalog/create/resume/history awaits and before turn dispatch. Private native auth principal is rechecked at the operation boundary. Non-read credential/process actions reserve the owning profile before awaits, retire owner work/processes, and reject owner create/resume/send while mutation is pending. Native account updates during active work retire the owner conservatively, requiring explicit verification/resume. Native quota, Stop, child death and logout leave the sibling usable. Unknown auth actions reject before reservation, process retirement or native requests.
