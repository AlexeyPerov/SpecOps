# First-party optional agent registration

A supported agent is registered by a reviewed SpecOps application release. Catalogs select finite payload versions; they cannot add runtime IDs, descriptors, JavaScript adapter factories, trust keys, URLs or executable entry names to the running application.

## Required source contract

1. Add a finite runtime/component ID to the native component enum, WebView descriptor union, static capabilities, supervisor mapping and shipped lazy factory. Supply a stable label, native session/history ownership, account states, typed native interaction methods and Software recovery behavior. Discovery must neither load vendor SDKs nor start Node/native processes.
2. Ship an adapter revision independent of the vendor SDK version. Maintain exact app/host/adapter/native-store compatibility; managed host resolution must check the vendor pin, adapter revision, target and every file before imports or launches. A worker protocol change requires a reviewed adapter revision/catalog release even when the vendor package version is unchanged. Shared Node is an exact dependency, never a copy inside an agent component.
3. Supply a finite CI recipe with SDK transitive chunks, native binaries/libraries, workers/parsers/search/sandbox helpers and notices. Review official source/archive identity, legal distribution, native signing and quarantine behavior. Candidate reconstruction and downloaded hashes alone do not provide redistribution approval.
4. Sign immutable manifests/catalogs with release trust and approved origins after review. Include exact dependencies, approved executables, architecture, complete files/modes/hashes and finite entry names. Reuse the existing native plan/install/receipt/lease/remove machinery; no install scripts or package manager run on the user's machine.
5. Prove source discovery, missing-component recovery, create/send/cancel/resume/history/auth/policy/profile isolation with bounded fixtures. Then run real no-account copied control/helper probes and authenticated A/B account isolation, native-store resume and clean signed installed tests. Record pass, failed, unavailable and not-run separately.

The shipped fixture factory in `registration.test.ts` exercises deferred registration, one construction for concurrent activation and rejection of arbitrary URL IDs. The copied real-candidate harness also activates this shipped fixture against a managed native dependency and reads its common descriptor after finite candidate extraction, joining the install/resolve/descriptor contract without installer changes. The signed all-five synthetic fixture pipeline covers receipts/dependencies/leases; adding a future production ID still requires the source changes and fresh installed acceptance above. This fixture is not a third-party adapter loader.

## Independent dependencies and reviewed group removal

Any selected agent installs against one compatible shared Node component. Install plans retain complete dependency identities while download/disk totals include only absent or invalid software. If a prerequisite changes after review and more bytes would be downloaded, confirmation fails as stale and requires a fresh plan. A failed sibling leaves valid Node and other agents installed; account/profile/history storage is outside software roots.

An explicit group removal review must enumerate exact installed component/version identities, all dependents and active leases. Stop owned host/native workers before removing a leased version. Remove each selected dependent before its shared prerequisite; retain Node while any unselected installed dependent remains. Recompute dependencies and leases before each removal and stop on a new conflict. Group removal is a sequence of existing guarded native removals, not an atomic delete or profile/history purge. The Software UI must present the resulting group and retained prerequisites before executing it; its implementation belongs to maintenance UX in G.
