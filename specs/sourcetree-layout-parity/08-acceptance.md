# GL-08 — Визуальная и сценарная приёмка

**Статус:** Planned. **Зависимости:** GL-01…GL-07.

## Матрица проверки

- [ ] Снять History, Changes, Pull и Push в реальном SpecOps на 1440×900 и 1920×1080 CSS px; отдельно проверить 1024×768 и 800×600. Записать ОС, масштаб, тему и размеры viewport.
- [ ] Сопоставить с оригиналами композицию, порядок областей, плотность, разделители, заголовки, выделение и scroll. Шрифты/цвета адаптировать к теме SpecOps; попиксельное копирование не является целью.
- [ ] Проверить светлую/тёмную тему, увеличение интерфейса, длинные пути/refs, пустой repo, detached HEAD, bare repo, отсутствие remote, offline/error/auth и выполняющуюся операцию.
- [ ] Проверить весь цикл мышью и клавиатурой: ref → commit → file → diff; Changes → stage → commit; открыть Pull/Push → изменить поля → отменить; фактические remote-операции только на временных тестовых repo.
- [ ] Проверить resize и восстановление layout, смену workspace/окна, внешние изменения Git, быстрые переключения и поздние ответы.
- [ ] На истории 5000+ коммитов и ветвящемся графе записать задержку выбора и прокрутки, число DOM/SVG элементов, пределы загрузки. Регрессии относительно текущего приложения исправить, не объявлять полную виртуализацию по одному списку строк.

## Автоматические проверки

- [ ] Фокусные mounted component tests для layout, selection, modal validation, focus, stale responses и очереди операций.
- [ ] Реальные временные Git-repo tests для новых аргументов Pull/Push, tracking, частичных отказов и отмены. Fixtures без имён и данных с пользовательских скриншотов.
- [ ] Svelte/type check, production frontend build, релевантные frontend tests; native tests при изменении IPC/argv/процессов.
- [ ] Проверка Svelte-компонентов по действующим инструментам проекта. Для документационного пакета запуск приложения/тестов не является доказательством реализации будущих задач.

## Definition of done

- [ ] Все задачи GL-01…GL-07 приняты; нет открытых обязательных Git-зависимостей или фиктивных активных кнопок.
- [ ] В папке evidence сохранены датированные реальные снимки и краткая таблица passed/blocked/not-run с командами и результатами проверок. Создать evidence при реализации, не подменять её референсами.
- [ ] Каждый пункт имеет проверяемое подтверждение; отдельные UI-only результаты помечены частичными.
- [ ] Changelog обновлён; нет регрессии существующего Git/editor workflow и миграций persisted data.

Реализация этого пакета подтверждает только описанный layout и remote-диалоги. Полный Git-паритет (частичный staging, merge editor, interactive rebase, LFS и прочее) требует отдельных спецификаций.
