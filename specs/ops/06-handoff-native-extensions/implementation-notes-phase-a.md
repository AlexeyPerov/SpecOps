## Packet and review

`sessionHandoff.ts`, `handoffController.ts` and `SessionHandoffDialog.svelte` implement the common Sessions Handoff action. Goal, manually entered decisions, common summary/recent text, relevant paths, changed-file list/patches and optional selected excerpts are separately editable/removable. The actual first prompt is displayed before confirmation. It includes neutral SpecOps source/target IDs, source/target runtime/profile, target model/mode and workspace; native source session/turn/item IDs are not copied. No native history/account transfer occurs. Frozen approval bytes and target selection remain unchanged across a failed confirmation/catalog refresh. Saved unsent approvals are opened for review before confirmation; known sent/uncertain targets offer open/resume without resend.

Default evidence excludes raw tool input/output, reasoning and hidden/credential-shaped files. Common secret values/credential-assignment lines and complete private-key blocks are redacted before truncation. Arbitrary secrets cannot be inferred from innocent-looking prose: explicit human review/removal remains necessary. Each section is bounded to 8,192 characters, the prompt to 65,536; 12 recent common messages, 32 sorted paths/excerpts, first eight tracked patches and 8,192 bytes per excerpt are finite defaults. Missing evidence, excluded counts and truncation are visible. A missing git repository/HEAD is explicit; untracked file patches are not collected. Existing native git execution has bounded output/timeouts (16 MiB output ceiling), disables external diff/text conversion and uses literal relative pathspecs. No files or source native history are mutated by drafting.

`handoff.rs` reads excerpts with directory-descriptor-relative `openat`, `O_DIRECTORY`/`O_NOFOLLOW` traversal and a final no-follow, nonblocking regular-file read. Every ancestor is anchored, preventing parent symlink swaps from escaping the selected workspace. Binary, invalid UTF-8, private/traversal/missing/link content is omitted. Unix implementation is source-tested on Darwin arm64; other platforms report unavailable excerpt evidence until a safe handle-relative implementation is verified.

## Intent, lineage and recovery

The private workspace app-data `handoffs.json` journal is bounded to 64 attempts and 1 MiB total. A bounded native no-follow reader and exhaustive source codec reject malformed/oversized/mismatched workspace/native target data. Journal writes use an exclusive directory-relative lock, expected-content CAS, `create_new` 0600 temporary file, file fsync, atomic rename and directory fsync. There is no debounce, delete-before-rename or truncating fallback. Two independently loaded window snapshots cannot both cross an intent transition. A stale lock fails closed and requires inspection of the interrupted attempt before manual recovery; no stale-owner guessing is used. Native Unix storage is mandatory for confirmation; unsupported platforms fail before native creation. Filesystem/power-loss behavior and other-platform implementations remain installed acceptance gates.

The sequence is approved → create-intent → created (known native reference) → send-intent → settled. Each transition is awaited before its corresponding native action. Failed validation/auth/catalog blocks creation. A lost create acknowledgement leaves create-intent: no automatic second native thread is created. A known created target can resume reviewed unsent context without another create. Send intent remains after cancellation, timeout, lost response or local save failure; a possibly accepted first prompt is never automatically resubmitted. A failure to save the native acknowledgement conservatively keeps the create intent; recovery requires native-history inspection. These conservative uncertainty states favor an explicit known/unknown outcome over guessing delivery.

Lineage is stored independently in the session index and common thread metadata, including the initial user-message ID and target profile. It is not injected into vendor settings/history. Index markers survive corrupt/divergent thread caches and enforce the single-use initial-send permit in the production pipeline. Target profile/runtime/model/mode/policy remain immutable; ordinary Retry of the first handoff message is blocked even after cache loss. Opening a known target performs explicit native resume/history reconciliation and sends nothing. The source remains usable under its original binding.

Integration found and fixed a shared store bug: draft promotion previously discarded an already-created binding when the first user message was appended. Promotion now preserves binding/lineage and only removes the draft flag, preventing a second hidden native target. Existing pre-create sends retain their behavior.
