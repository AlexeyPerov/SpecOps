# GL-07 — Окно Push

**Статус:** Planned. **Зависимости:** GL-05; расширение push API и native contract для нескольких refspec и tracking.

![Референс окна Push](references/push-dialog.png)

## Layout и взаимодействия

- [ ] Открывать modal с remote selector и URL, группой Branches to push, таблицей Push / Local branch / Remote branch / Track, Select all, Push all tags и нижними Cancel / Push.
- [ ] Каждая локальная ветка имеет независимый checkbox, редактируемую удалённую цель и явное tracking-состояние. Не трактовать значок с минусом на снимке как готовую семантику: SpecOps показывает понятные track / do not change и текущее upstream отдельно.
- [ ] По умолчанию выбирать текущую ветку при допустимом HEAD; целевую удалённую ветку выводить из upstream выбранного remote, иначе явно предлагать одноимённую ветку.
- [ ] Push all tags по умолчанию выключен; значение на референсе не является требованием автоматически отправлять все теги.
- [ ] Select all действует на строки веток, не включает теги. Изменение remote пересчитывает удалённые refs и tracking, не использует назначения старого remote.
- [ ] Поддержать длинные имена, внутренний скролл, loading/empty/auth/error states. Проверять ref names, пустые назначения и дублирующиеся удалённые цели до запуска.
- [ ] Primary action требует хотя бы одну выбранную ветку или явный режим tags-only. Detached HEAD не подставляется скрыто вместо выбранной ветки.
- [ ] Escape/Cancel до запуска закрывает окно без мутации. Выполнение показывает progress, итог по refs и Cancel operation; повторная отправка во время busy исключена.

## Git-зависимости, обязательные для рабочих контролов

- [ ] Добавить типизированный push plan: remote, список точных source SHA/local refs → destination refs, tracking и tags; перепроверять источники перед выполнением, не заменять все строки на HEAD.
- [ ] Расширить существующий push одного target на несколько refspec. Определить per-ref результат и частичный успех; атомарность не обещать без подтверждённой поддержки сервера.
- [ ] Настраивать upstream только для успешно отправленных веток с выбранным Track; не перепривязывать остальные локальные ветки. Проверить допустимые native config/branch формы, поскольку текущие config/remote формы ограничены.
- [ ] Push all tags — самостоятельная явная операция/часть плана; сообщение об успехе отражает ошибки отдельных refs/тегов. Не добавлять force или удаления refs в layout-задачу.
- [ ] Сохранить авторизацию, очередь, отмену и refresh; после ошибки/отмены перечитать фактические remote/local tracking states, не повторять возможно выполненный push автоматически.

## Приёмка

- [ ] Таблица и группы соответствуют референсу, выбор веток/тегов очевиден перед отправкой, tab order и возврат фокуса работают.
- [ ] На временном локальном bare remote проверены одна/несколько веток, новое имя назначения, track on/off, tags-only и branches+tags.
- [ ] Проверены отказ non-fast-forward, частичный успех и отмена; диалог не сообщает общий успех при отклонённом ref.
- [ ] До закрытия Git-зависимостей layout можно принять отдельно, но задачу целиком нельзя отметить Done.
